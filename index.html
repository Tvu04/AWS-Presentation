Introduction

Where storage fits

04

Core AWS services

We've already looked at three of the core AWS service areas: Amazon Virtual Private Cloud, or Amazon VPC, for networking; Amazon Elastic Compute Cloud, or Amazon EC2, for compute; and AWS Identity and Access Management, or IAM, for managing access. This module adds another core area, which is storage.

AWS offers several kinds of storage, and each one serves a different purpose. Instance store, sometimes called ephemeral storage, is short-term storage that's built into an EC2 instance. Once the instance stops, whatever was on it is lost. Amazon EBS is long-lasting storage that attaches to an EC2 instance as a drive. A volume can only connect to an instance in its own Availability Zone, and only to one instance at a time. Amazon Elastic File System, or Amazon EFS, is a file system that many EC2 instances can share and use at the same time. Amazon S3 saves each file as an object with its own URL, so it can be reached from anywhere. Finally, Amazon S3 Glacier is low-cost cold storage for data you seldom need, such as long-term archives or compliance records.

The main difference to keep in mind is how each one is shared and how long the data lasts. Instance store is fine for temporary data like caches or scratch files. EBS is for data that one server needs to keep. EFS is for files that several servers need at once. S3 and S3 Glacier are for data that needs to be reachable over the internet or kept for a long time. Picking the right one comes down to speed, sharing, durability, and cost.

For this presentation, I'll focus on two of these: Amazon EBS and Amazon S3.

Amazon Elastic Block Store

Overview
05

Section 1 title

Let's begin with Section 1, which covers Amazon Elastic Block Store, or Amazon EBS.

In this section, I'll explain what EBS is, compare block and object storage, go over the different volume types, and cover its main features and pricing. Then we'll see a demo and go through Lab 4.

06

Storage: Amazon EBS

Amazon EBS gives EC2 instances storage volumes that keep their data long term. When storage is persistent, or non-volatile, the data is still there after the device loses power, the same way your laptop keeps your files after you shut it down.

AWS automatically copies every EBS volume within its Availability Zone, so a single hardware failure won't cost you your data. EBS is built to be highly available and durable, and it delivers steady, low-latency performance for your workloads. You can also adjust how much storage you use within minutes, and you're only charged for the amount you provision.

One thing to remember is that an EBS volume lives in a single Availability Zone. That's why it can only attach to an EC2 instance in that same zone. If you need the data somewhere else, you'd use a snapshot to move it, which I'll talk about in a few slides.

07

Block storage versus object storage

Let's think about a quick scenario. Suppose you need to change just one character in a file that's 1 gigabyte in size.

Pause

With block storage, only the block holding that character needs to change. With object storage, you have to update the whole file.

This is one of the most important differences between storage types, because it affects throughput, latency, and cost. In general, block storage is faster and uses less bandwidth, but it may cost more than object storage.

To connect this to AWS services: Amazon EBS is block storage, so it works well for data that changes often in small pieces, like a database or an operating system. Amazon S3 is object storage, so it's a better fit for whole files that don't change much once they're saved, like photos, videos, and backups. Knowing which type you need is the first step in choosing the right service.

Volumes and volume types
08

Amazon EBS

Amazon EBS lets you set up separate storage volumes and connect them to an EC2 instance. You can think of a volume as an external hard drive for your server: it's reliable, it can be detached, and it stores data in blocks. Since the volume connects directly to the instance, data moves between them with very little delay. That makes EBS a strong option for running a database on EC2, such as the database behind an online store that has to record every order right away.

When you back up an instance as an Amazon Machine Image, or AMI, its EBS volumes are included. Those AMIs are kept in Amazon S3, and you can use them later to launch new instances.

Backing up an EBS volume is done with a snapshot. The very first one is called the baseline snapshot. Each snapshot after it only records the changes made since the one before.

Typical uses for EBS include boot volumes and storage for EC2 instances, data storage with a file system, database hosts, and enterprise applications.

Another helpful detail is that you can detach an EBS volume from one instance and attach it to a different instance in the same Availability Zone. So if a server has a problem, you can move its data volume to a new server without losing anything. And because snapshots only save the changes, they take less time and storage than making a full copy every time.

09

Amazon EBS volume types

One of the best ways to save on storage is to choose the volume type that fits your workload. EBS volumes fall into two groups: solid state drives, or SSDs, and hard disk drives, or HDDs.

IOPS stands for input/output operations per second, which measures how many reads and writes a volume can handle. General Purpose SSD reaches up to 16,000 IOPS per volume, while Provisioned IOPS SSD reaches up to 64,000. The HDD types are much lower, with 500 IOPS for Throughput-Optimized and 250 for Cold. Each type supports volumes as large as 16 TiB.

If you need top performance, Provisioned IOPS SSD is the strongest option. But if your application won't use that much speed, General Purpose SSD will usually do the job. Keep in mind that only SSD volumes can serve as boot volumes for EC2. The less expensive HDD types are better suited for additional storage.

An easy way to remember the difference is that SSDs are best at many small, random reads and writes, which is what databases and operating systems do. HDDs are best at reading large amounts of data in order, like scanning through log files. Also, notice the table uses TiB and MiB. A tebibyte is slightly larger than a terabyte, but for our purposes you can think of them as about the same.

10

Volume type use cases

As we just covered, an EBS volume is durable block storage that attaches to one EC2 instance, and it keeps its data even if that instance is stopped or terminated. Which type to use depends on the job.

General Purpose SSD is the recommended choice for most workloads, including system boot volumes, virtual desktops, low-latency interactive applications, and development and test environments.

Provisioned IOPS SSD is meant for critical business applications that need consistently high performance, or more than 16,000 IOPS or 250 MiB per second per volume. Large database workloads are a common example.

Throughput-Optimized HDD works best for streaming workloads that need fast, consistent throughput at a low price, like big data, data warehouses, and log processing.

Cold HDD is designed for large amounts of data that are rarely accessed, when keeping storage costs as low as possible is the priority. Neither HDD type can be used as a boot volume.

A common approach is to start with General Purpose SSD, watch how the application performs, and then switch types if needed. Since EBS volumes are elastic, changing the type later doesn't mean starting over.

Features and pricing
11

Amazon EBS features

There are three key features of EBS to know.

The first is snapshots. To make your data even more durable, EBS lets you capture a snapshot of a volume at a specific moment and build a new volume from it whenever you need to. Snapshots can also be shared or copied to other AWS Regions, which helps with disaster recovery. For instance, you could encrypt a snapshot in Virginia and send a copy to Tokyo.

The second is encryption. EBS volumes can be encrypted for free, which means data traveling between the EC2 instance and the volume inside AWS data centers is protected.

The third is elasticity. As a business grows, it usually needs more storage. EBS volumes can be made larger or switched to a different type. You could move from HDD to SSD, or expand a 50-GB volume up to 16 TB, all without having to stop the instance.

A few more details on these features. Snapshots can be scheduled automatically, so you don't have to remember to take them by hand. When a volume is encrypted, the snapshots made from it are encrypted too, and any volume you create from those snapshots is also encrypted. EBS encryption uses keys managed through AWS Key Management Service, or AWS KMS, so you don't have to build your own encryption system.

12

Volumes, IOPS, and pricing

When you're figuring out what EBS will cost, there are a few things to look at.

Volumes: every volume type is billed based on how many gigabytes you provision each month, and that continues until you release the storage.

IOPS: this depends on the type. For General Purpose SSD, I/O is already included in the price. For magnetic volumes, you're charged for the number of requests you send to the volume. For Provisioned IOPS SSD, you also pay for the IOPS you provision, based on the share of the month you have it.

EBS pricing has a lot of details, but the general idea is that you pay for the size of your volume and how much you use it.

Here's an example. If you create a 100-GB General Purpose volume but only store 10 GB of data on it, you're still billed for the full 100 GB. That's why it's a good habit to size volumes to what you need and to delete volumes you're no longer using. Unattached volumes keep costing money until they're deleted.

13

Snapshots and data transfer

Snapshots: EBS lets you save snapshots of your data to Amazon S3 so you can recover it reliably. Storing them adds a cost per GB-month.

Data transfer: incoming data is free. However, copying snapshots from one Region to another means you pay for the data that gets transferred. Once the copy is in the new Region, the usual snapshot storage rates apply there.

Because snapshots are incremental, you mostly pay for the data that changed between them, not for a full copy each time. Still, old snapshots add up over time, so many companies set rules to delete snapshots after a certain number of days or weeks.

Takeaways, demo, and Lab 4
14

Section 1 key takeaways

To summarize Section 1, Amazon EBS gives EC2 instances block-level storage volumes. These volumes live outside the instance and keep their data no matter what happens to the instance, so they work like virtual hard drives in the cloud.

EBS offers SSD and HDD volume types, and each has its own performance level and price, so you can match storage to what your application needs. EBS also replicates volumes within the same Availability Zone, makes encryption simple, lets volumes grow, and supports backups through snapshots.

In short, EBS is the go-to storage when one EC2 instance needs fast, reliable access to data that changes often. We'll see all of these ideas put into practice in the demo and the lab.

Section 2 · Slides 21–35

Amazon Simple Storage Service

Overview
21

Section 2 title

Next is Section 2, Amazon Simple Storage Service, or Amazon S3. Today's companies need to gather, store, and analyze huge amounts of data, and they need to do it easily and securely. S3 is object storage designed to hold and return any amount of data from any source, including websites, mobile apps, business applications, and Internet of Things, or IoT, sensors and devices.

In this section, I'll cover what S3 is, its storage classes, how buckets and URLs work, how S3 keeps data safe and scales, common use cases, and how pricing works. Then we'll finish with a demo.

22

Storage: Amazon S3

Because S3 is object-level storage, editing part of a file means making your change and then uploading the whole file again. In S3, data is saved as objects, and those objects are kept in containers called buckets.

Each object in a bucket is identified by a key, which is basically its name. Even though the console shows folders, S3 doesn't really have a folder structure like your computer does. A "folder" is just a shared prefix at the start of the key, like images/ or reports/.

Now let's take a closer look at S3.

23

Amazon S3 overview

S3 is a managed storage service in the cloud. It's built to grow without any effort on your part, and it's designed for 11 nines of durability. A bucket can hold almost any number of objects, and you can write, read, and delete them as needed. Each object can be as large as 5 TB. By default, S3 keeps redundant copies of your data across several facilities, and on several devices within each one.

Every bucket name is global, which means no two buckets in all of S3 can share the same name.

Your data isn't linked to a specific server, and you don't have to manage any infrastructure. An object can be nearly any kind of file, like photos, videos, server logs, or even database snapshots. You can control exactly who can reach your data using IAM policies, bucket policies, and access control lists on individual objects. Unless you change the settings, none of your data is public.

S3 also has a few extra features worth mentioning. You can encrypt data while it's being transferred, and you can turn on server-side encryption for stored objects. Event notifications can alert you or trigger other actions, like running an AWS Lambda function, when an object is uploaded or deleted. And storage class analysis looks at how often your data is accessed, so you can tell when it makes sense to move data to a cheaper class like Standard-IA.

24

Amazon S3 storage classes

S3 provides several storage classes, each built for a different kind of use.

S3 Standard is for data you use often. It offers high durability, availability, and performance, which makes it a good fit for cloud applications, dynamic websites, mobile and gaming apps, and big data analytics.

S3 Intelligent-Tiering is meant to lower costs automatically. For a small monthly fee per object, S3 tracks how each object is used. If an object goes 30 days in a row without being accessed, it's moved to a cheaper tier. If it's used again, it moves back. This works well when you can't predict how often data will be used.

S3 Standard-Infrequent Access is for data that isn't used often but has to be available quickly when it is. It has a lower storage price with a retrieval fee, so it's good for long-term storage, backups, and disaster recovery files.

S3 One Zone-Infrequent Access keeps data in just one Availability Zone instead of at least three, so it costs less than Standard-IA. It's a good option for secondary backups or data that would be easy to re-create.

S3 Glacier and S3 Glacier Deep Archive are the lowest-cost options, designed for archiving.

You don't have to move data between classes by hand. With lifecycle policies, you can set rules like moving objects to Standard-IA after 30 days and to S3 Glacier after a year. The trade-off with the archive classes is retrieval time. Getting data back from Glacier can take anywhere from minutes to hours, depending on the retrieval option you choose.

25

Bucket URLs

To work with S3, there are a few basic ideas to understand. First, data in S3 lives in buckets. A bucket is a logical container for objects, and its name has to be unique across all of S3. You can have one or more buckets, and for each one you can control who's allowed to create, delete, and list objects.

To upload data like photos, videos, or documents, you create a bucket in an AWS Region and then add your objects to it. In this example, the bucket is in the Tokyo Region, which AWS identifies with the code ap-northeast-1.

You can write a bucket's URL in two different styles: path-style, where the Region comes first, and virtual hosted-style, where the bucket name comes first.

S3 calls files objects. An object includes the data itself and metadata that describes it, including a URL. In this example, the object Preview2.mp4 is stored in the bucket, and its name appears at the end of its URL.

When you upload an object, you can also set permissions on the data and its metadata. So you could make one file publicly readable for a website while keeping everything else in the bucket private.

How S3 stores and serves data
26

Data is redundantly stored in the Region

Every S3 bucket belongs to one specific AWS Region. When you save data to that bucket, S3 stores copies of it in multiple AWS facilities across the Region. It's built to keep your data intact even if two of those facilities lose data at the same time.

For most storage classes, those copies are spread across at least three Availability Zones in the Region. The exception is One Zone-IA, which keeps data in just one zone. Choosing the Region also matters for other reasons, like keeping data close to your users for faster access or meeting rules about where certain data has to be stored.

27

Designed for seamless scaling

As your data grows, S3 takes care of the storage behind your bucket on its own. You can start using it immediately, and it expands along with your application. It can also keep up with large numbers of requests. You never have to provision storage or throughput in advance, and you're billed only for what you actually use.

To give you a sense of scale, S3 holds trillions of objects and regularly handles millions of requests per second. That's why companies of every size can rely on it, from a student project to a major streaming service.

28

Access the data anywhere

There are several ways to get to your data in S3: the AWS Management Console, the AWS Command Line Interface, or CLI, or the AWS software development kits, also called SDKs. You can also reach a bucket's data directly through REST-based endpoints over HTTP or HTTPS. REST stands for Representational State Transfer, which is a common way for apps to talk to each other over the web. HTTP is Hypertext Transfer Protocol, and HTTPS is the secure, encrypted version of it.

For that kind of URL access to work, bucket names have to be unique around the world and DNS-compliant. DNS stands for Domain Name System, which is the system that turns web addresses into locations on the internet, so bucket names have to follow its naming rules. Object keys, which are the object names, should also use only characters that are safe in a URL.

If you don't want your data going over the public internet, you can also reach S3 privately from inside a VPC by using a VPC endpoint. This keeps traffic between your EC2 instances and S3 inside the AWS network.

29

Common use cases

Since S3 can hold almost unlimited data that's reachable from anywhere, it fits many different situations.

One use is as a central location for application data. Any instance of an application, whether it's on EC2 or a traditional server, can read from the same bucket. That's helpful for files like user-uploaded media and server logs. And because the content is available over the internet, clients can download it straight from S3 instead of going through your application.

Another use is static web hosting. A bucket can serve a website's static files, such as HTML, CSS, and JavaScript. HTML is Hypertext Markup Language, which builds the page, and CSS is Cascading Style Sheets, which controls how it looks.

S3 is also a strong choice for backups because it's so durable. For even better availability and disaster recovery, you can turn on cross-Region replication, which automatically copies data from a bucket in one Region to another Region.

Lastly, S3 can act as a staging area for big data before it's analyzed.

For example, a company might send its daily sales records and website click data into S3, then use analytics tools to find trends later. S3 works well here because it can hold huge amounts of raw data cheaply until someone is ready to use it.

30

Amazon S3 common scenarios

Here are a few common ways businesses use S3. Backup and storage, for companies that offer backup services to others. Application hosting, for services that deploy, install, and manage web applications. Media hosting, for building reliable, scalable infrastructure that handles video, photo, or music uploads and downloads. And software delivery, for hosting applications that customers can download.

What these scenarios have in common is that they all need storage that's durable, can grow without limits, and can be reached from many places. Those are exactly the strengths of S3 that we've talked about so far.

Pricing, takeaways, and demo
31

Amazon S3 pricing

What you pay for S3 depends on the Region and the types of requests you make. You're only charged for what you use, including the gigabytes you store each month, data sent out to other Regions, and requests such as PUT, COPY, POST, LIST, and GET.

As a general rule, you only pay for transfers that cross your Region's boundary. That means there's no charge for transferring data into S3, or for sending data from S3 to Amazon CloudFront or to EC2 in the same Region.

If you want to estimate costs before you build something, AWS offers the AWS Pricing Calculator, where you can enter how much you plan to store and how many requests you expect.

32

Storage pricing, part 1

When estimating S3 costs, there are a few things to look at.

Storage class: S3 Standard is built for 11 nines of durability and four nines of availability. S3 Standard-Infrequent Access is a way to save money on data you don't use as often. It still has 11 nines of durability, but it offers three nines of availability over a year. Each class is priced differently.

Amount of storage: this is how many objects you keep in your buckets and how large they are.

This is where choosing the right storage class really pays off. Data that's used every day belongs in Standard, but data that's only opened a few times a year can usually be stored more cheaply in Standard-IA or an archive class.

33

Storage pricing, part 2

Requests: think about how many requests you make and what kind they are. GET requests are priced differently from other types, like PUT and COPY. A GET request retrieves an object and requires READ access. A PUT request adds an object to a bucket and requires WRITE permission. A COPY request duplicates an object that's already in S3, which is the same as doing a GET and then a PUT.

Data transfer: look at how much data leaves the S3 Region. Bringing data in doesn't cost anything, but sending data out does.

For example, a popular website that serves the same image to millions of visitors will have a lot of GET requests and outbound data transfer. A backup bucket, on the other hand, mostly receives uploads, so its costs come mainly from storage. Knowing how your data will be used helps you predict the bill.

34

Section 2 key takeaways

That completes our introduction to Amazon S3, including its main features and some common use cases. To recap, S3 is a fully managed cloud storage service. It can hold a virtually unlimited number of objects, you only pay for what you use, and you can get to your data anytime, from anywhere, using a URL. It also comes with strong security controls.

To compare the two services we covered today: EBS is block storage attached to a single EC2 instance in one Availability Zone, built for fast, frequent changes. S3 is object storage that's reachable from anywhere, scales without limits, and is built for durability. Many real applications use both, with EBS running the server and database and S3 holding files, backups, and media.
